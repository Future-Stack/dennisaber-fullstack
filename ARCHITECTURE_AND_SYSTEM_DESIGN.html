Technical Architecture & System Design

Dennis Besseler Course Portal

Platform: Laravel 11/12 Full-Stack • Version: 1.0.0 (Phase 1 Final & Phase 2 Ready) • Architecture: MVC + Service Layer

1. Executive Summary & Core Philosophy

The Dennis Besseler Course Portal is an enterprise-grade learning management and audio-first media delivery system designed around strict architectural, pedagogical, and security principles:

🎯 Clean Separation of Concerns

Complete structural and technical decoupling between the public marketing & sales portal (besseler.de) and the dedicated, protected learning platform (besseler-kursportal.de).

🎧 Audio-First Course Pedagogy

Engineered for high-retention audio lectures, guided reflection, and embedded PDF workbooks without distracting visual elements or intrusive course frameworks.

🛡️ Strict Intellectual Property Protection

Dynamic server-side PDF license watermarking, cryptographic single-device binding, and protected media streaming via authenticated HTTP range requests (zero direct download links).

💳 Transparent Single-Payment Model

No recurring subscriptions, no third-party tracking scripts or payment gateway cookies on the portal, and deterministic course access durations (30 or 90 days).

2. High-Level Software Architecture

The platform follows a layered Model-View-Controller (MVC) + Service Layer Architecture built on Laravel, utilizing PHP 8.2+, SQLite/MySQL, Blade templating, and vanilla JavaScript (zero heavy SPA frameworks to ensure high performance and maximum stability).

3. Core Subsystems & Security Architecture

3.1. Authentication & Single-Device Binding Engine

To eliminate credential sharing and unauthorized account proliferation, the platform implements a Cryptographic Single-Device Binding Mechanism:

  1. Fingerprint Generation: When a user accesses any login form, a client-side JavaScript routine gathers hardware and browser characteristics (navigator.userAgent, platform, screen.width, screen.height, Intl.timezone) and computes a SHA-256 cryptographic hash (device_id).
  2. First-Login Dynamic Binding: When a customer logs in for the first time, if device_id is null on their record, the system automatically binds the hash to their account and timestamps last_device_activity_at.
  3. Subsequent Access Verification: On all subsequent login attempts, the system validates the incoming device hash against the stored hash. If there is a mismatch, login is blocked with an explicit German security notice.
  4. Admin 2FA Security Code: The admin login requires an email/password plus a separate hashed Security Code (default 1979).
  5. Administrative Device Reset: Admins can reset a user's bound device with a single click in the Admin Panel whenever a legitimate customer changes hardware.

3.2. Protected Media Delivery & Dynamic Watermarking

All course files (Audio MP3s, Video MP4s, and PDF Workbooks) reside in non-public storage directories and are never exposed via raw static web URLs.

Request: /kurs/{courseSlug}/lektion/{lessonSlug}/media?type=audio
  │
  ├── 1. Check Authentication (Member or Admin)
  ├── 2. Check Course Enrollment & Active Expiration Date
  ├── 3. Determine MIME Type & File Size
  ├── 4. Audio/Video -> Handle HTTP 206 Partial Content (Byte Range Requests)
  └── 5. PDF -> Pass through PdfWatermarkService -> Inject Personalized Stamp -> Output inline
Key Media Streaming Capabilities:
  • Range Request Streaming: Supports HTTP/1.1 206 Partial Content with Accept-Ranges: bytes, enabling instant 10-second skip forward/back and variable speed playback (1.0x, 1.25x, 1.5x) without buffering delays.
  • Dynamic PDF Watermarking: Every rendered PDF contains server-side customer license watermarks (PRIVAT-LIZENZ · [First Name] · [RE-Number]).
  • In-Page Embedding: Workbooks are embedded via in-page viewer iframe with #toolbar=0&navpanes=0 and fullscreen toggle without external download triggers.
